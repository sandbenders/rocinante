# phases.md: rocinante

The history of rocinante's closed phases: what each one set out to build, what it found and measured, and how it met its exit. It was moved out of `CLAUDE.md` on 2026-10-30 to keep that file short, and it is not imported into every session: read it when later work builds on a closed phase (Phase 8's packaging needs the Phase 0 findings on Android and iOS; Phase 7 compares the compiled sketch with Phase 2's interpreter figures). It records history, not decisions: a decision that still binds is in `CLAUDE.md` §10, and the plan for the phases still to come is in `CLAUDE.md` §8. Section numbers (§4.7, §10) are `CLAUDE.md`'s and `docs/design.md`'s.

### Phase 0: Foundations (done 2026-10-27)

Phase 0 built the repository, the build script with its `ci` command, the hooks, both pipelines, the licence check and the unit-test setup (§9, §11), and tested the riskiest assumptions with four throwaway spikes in `spikes/`: (1) an SDL3 window and GPU device on every desktop system, FreeBSD on Vulkan through Mesa included; (2) an Odin and SDL3 program drawing a shader circle on a real iPhone and a real Android phone; (3) a hand-written typed IR run by an interpreter and turned into Odin, with a stand-in `roci doctor`; (4) Dear ImGui through dear_bindings with the SDL3 and SDL_GPU backends, a text box with IME, and an AccessKit adapter read by a screen reader. It also checked every dependency, the name, the parity map (§6) and Odin's target coverage. What later phases need is below; per-platform run details are in git history.

**Phase 0 results** (recorded 2026-10-24 to 2026-10-27):

- **Odin:** pinned to `dev-2026-10`. Official archives cover Linux amd64 and arm64, macOS arm64 and Windows amd64 only (§4.7). Homebrew's `dev-2026-07` (LLVM 23) failed to compile any program; its `dev-2026-10` (LLVM 22.1.8) works. On FreeBSD (15.1) the pinned release builds from source in about 2 minutes with `LLVM_CONFIG=llvm-config19 gmake release-native` (it needs `gmake`, git and the ports package `llvm19`, because the base system's clang has no `llvm-config`, so `roci` must find it under its versioned name) and reports the same commit as the official archives.
- **`vendor:sdl3`:** its bindings are for SDL 3.4.2 while the latest release is 3.4.18. Patch releases keep the ABI, so the bindings load the newer library, but functions added after 3.4.2 are missing; nothing so far needed one. Results from SDL 3.4.2, 3.4.16 and 3.4.18 count as the same SDL (decided 2026-10-26).
- **Name check** (2026-10-24; registries and GitHub queried directly, no legal search): FreeBSD already has a port `sysutils/rocinante` (BastilleBSD's tool), so ours is named `roci`; `roci` is free as a command on Homebrew, the AUR and Repology (a small crates.io library, an npm package and a dormant PyPI package use the name, none a creative-coding tool); `rocinante` is taken on npm and PyPI by unrelated web frameworks and free on crates.io and Homebrew (we publish to none); the GitHub organisation `Rocinante` is taken, so the mirror is `github.com/sandbenders/rocinante`; no creative-coding project of either name was found (not exhaustive). `rocinante.dev`, `.org`, `.io`, `.run` and `roci.dev` resolve; `rocinante.art`, `.studio`, `.codes` and `roci.sh` did not. **Still to do by hand:** a trademark search for software classes (EUIPO, WIPO, USPTO) and a manual web search.

- **Spike 1, desktop** (now `roci/platform` and `examples/window`): passed on macOS (Metal), FreeBSD 15.1 and CachyOS Linux (Vulkan, so GPU rendering works on FreeBSD even though SDL does not list it) and Windows 11 (Direct3D 12; Odin's `vendor/sdl3/SDL3.dll` must sit beside the program).
- **Spike 3, code generation** (`spikes/codegen`): passes on all four desktop systems; the interpreter and the generated Odin print identical output and both call the same `verbs` procedures. Generated code names variables after the sketch, comments each statement with its `.roci` line and declares every assigned name once at the top (how the §5.15 scope rule maps onto Odin); each record shape becomes a plain struct, a list a `[dynamic]` array and `for each` a `for &p in` loop (the layout §5.2 promises). Found: on Windows the generated program's `-out:` path must end in `.exe`, and without the Visual Studio C++ workload Odin stops with "VS library path not found" (Build Tools via `winget install --id Microsoft.VisualStudio.BuildTools` with the `Microsoft.VisualStudio.Workload.VCTools` workload; `doctor` finds them through `vswhere`).
- **Spike 4, UI** (`spikes/ui`; Dear ImGui v1.93.0, dear_bindings v0.26 and accesskit-c 0.23.1 built into `.cache/ui` by `setup.sh` and `setup-windows.sh`, nothing committed): dear_bindings generated the C API for `imgui.h` and for **both `imgui_impl_sdl3` and `imgui_impl_sdlgpu3`**; a slider, a button and a text box draw through them with keyboard navigation on all four desktop systems. accesskit-c builds from source (CMake and cargo); on macOS its adapter attaches to SDL's window and the tree is built from rocinante's own widget records. **Checked by hand (2026-10-26):** VoiceOver reads and drives the three widgets; IME composition works on macOS and with the Microsoft Japanese IME on Windows (Dear ImGui's default font has no Japanese glyphs until Phase 3 brings real fonts). Found: dear_bindings needs Python and `ply` only to generate (a throwaway virtual environment; Python stays out of the build until Phase 6); `imgui_demo.cpp` must be compiled because `dcimgui.cpp` wraps its functions; accesskit-c's enumerators are one byte wide and its struct layouts differ from a guess, so real bindings must be generated from `accesskit.h`; its SDL example is for SDL2, so SDL3 needs `SDL_PROP_WINDOW_COCOA_WINDOW_POINTER`; on Windows Odin links the static C runtime, so C++ libraries are built with `-MT` (and dear_bindings under Windows Python needs Windows paths, `cygpath -m`); Dear ImGui writes `imgui.ini` in the working folder (ignored by git). **Not verified:** the Windows (UI Automation), Linux and FreeBSD (AT-SPI) adapters, and IME on Linux and FreeBSD; FreeBSD's screen-reader support stays an open question (§4.8).
- **Spike 2, Android** (Pixel 9, Android 16, Mali-G715) drew a shader circle at 60 fps on Vulkan from an Odin shared library inside SDL's Java activity. Findings that shape the core and `roci package android`: SDL's Vulkan backend requires `shaderClipDistance` by default and the Mali reports it unsupported, so the core creates the device with `SDL_PROP_GPU_DEVICE_CREATE_FEATURE_CLIP_DISTANCE_BOOLEAN` off and shaders may not use clip distances (`adb shell cmd gpu vkjson` shows a phone's features); `vendor:sdl3` declares `SDL_main` as an import, so the core exports its own `rocinante_main` and the Java activity overrides `getMainFunction()` (worth offering upstream); Odin always links the NDK's `native_app_glue`, which needs an exported do-nothing `android_main`; on Apple Silicon `ODIN_ANDROID_NDK_TOOLCHAIN` must point at the NDK's `darwin-x86_64` toolchain, which Odin does not guess; a new debug key on each build makes the phone refuse the update (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), so the key must be kept; `javac`, `d8` and `apksigner` need a JDK, which `roci` fetches (§4.7); the APK is assembled by hand with `aapt`, `zipalign` and `apksigner` because `odin bundle android` cannot add Java code; a locked or sleeping phone fails with `VK_ERROR_SURFACE_LOST_KHR` or draws nothing.
- **Spike 2, iOS** (iPhone 13 Pro, iOS 26.6.2, Xcode 27.1, a free Apple ID) drew the same circle at 60 fps on Metal (the shader goes SPIR-V to Metal through `spirv-cross`, which renames the entry point `main0`). No Xcode GUI: SDL as a static `libSDL3.a`, Odin builds the sketch with `-target:darwin_arm64 -subtarget:iphone -build-mode:lib`, `clang` links, a tiny generated Xcode project only wraps and signs it, `xcrun devicectl` installs and launches. Findings: Odin's own link step puts Homebrew's macOS `libSDL3.dylib` ahead of the iPhone library, so the core builds a static library and links separately; `codesign` refuses the bundle until extended attributes are stripped (`xattr -cr`); a free Apple ID's apps stay untrusted until the user taps Trust and the signature lasts 7 days; the phone needs Developer Mode, unlocked and trusted for the Mac; an iOS app does not quit itself, so the core runs until the system asks and offers no `quit` there; `sdl.RunApp(0, nil, main_func, nil)` starts UIKit and calls the sketch's main on SDL's thread.

**Phase 0 exit** (2026-10-27). Every criterion is met: both pipelines green (GitLab on ORION, Arch; GitHub on Ubuntu 24.04, pinned) from the same `main`, running `odin run build -- ci`; spikes 1 to 4 pass as above; the parity map was verified against the three references (2026-10-24); Odin is pinned with its target coverage and gaps recorded (§4.7); hosts and targets are decided (§7).

**Carried into later phases** (none blocked Phase 1): the text engine choice (§4.3, start of Phase 3: SDL3_ttf's GPU engine was not tried); `vendor:sdl3` or our own bindings (decide the first time a newer function is needed); the AccessKit adapters for Windows, Linux and FreeBSD and IME on Linux and FreeBSD (Phase 3; the spike's hand-declared bindings are replaced by generated ones); the trademark search; the unchecked dependency platform lists; and offers to make upstream (Odin's `for x in m[key]` crash on a missing key, `SDL_main` as an import in `vendor:sdl3`, the bindings gaps). `spikes/` is throwaway; the packages in §4.2 are created as phases need them.

### Phase 1: Window and 2D core (Odin API) (done 2026-10-27)
- App loop, `window` with optional position, multiple windows, HiDPI.
- A minimal text path for the error overlay and debug output (a built-in bitmap font), so Phase 2 can show errors before Phase 3 brings real text (§4.3).
- Internal shader pipeline: HLSL → SPIR-V, Metal and DXIL, committed (below).
- Command list, batching, instancing, geometry cache.
- 2D primitives, style, colour, gradients (§5.9), transforms, basic shapes (including the tessellation decision, §4.3), math, random, noise, mouse and keyboard.
- First version of the stable verb ABI (§4.7), with its C ABI, and the verb registry it is generated with.
- Commands that describe themselves, lazy pipeline creation with a fallback, one seed per run with the single random and noise implementation (§4.7).
- Headless rendering and the golden-image harness (render offscreen, compare against reference PNGs with tolerance), which Phase 2 exposes as `roci run --frames`.
- Mobile: the Phase 1 examples running on an iOS device and an Android device.
- **Demo sketch**: `examples/garden`: a palette window sends tagged messages to a garden window with a gradient sky, noise-twinkling stars, a moon with radial and conic gradients, rainbow arcs, a quad hill, grass in a noise wind, flowers of turned gradient petals, a firefly on the mouse, clicks that plant and keys that calm and clear.
- **Exit**: `examples/circle.odin` and a 100,000-circle benchmark at 60 fps on every desktop at hand, with invictus (Xeon X5675 from 2010, the slowest computer at hand, standing in for a mid-range laptop) accepted at 57.8 (§10); drawing at a pixel density above 1 checked through the system's display scaling; two windows exchanging a message; runs on iOS and Android at 60.2 and 60.0 fps (2026-10-27).

**Phase 1 results** (all 2026-10-27; run-by-run detail is in git history):

- **Shaders:** SDL_shadercross has no tags or releases and is pinned at `1ff05bec573988a98ef9e0260b4da44f512b8367` in `SHADERCROSS_COMMIT`; its HLSL path needs DXC, which Microsoft ships only for Windows and x86-64 Linux, so on a Mac `shaders/compile.sh` runs the same steps by hand (HLSL to SPIR-V with glslang, SPIR-V to Metal with SPIRV-Cross) and `shaders/compile-dxil.sh` makes DXIL with `dxc` on Windows; both write the committed `shaders/compiled/`. Used only as build tools, so nothing is shipped. Its own `AGENTS.md` forbids AI-generated contributions (§3).
- **PNG output:** Odin's `core:image/png` only reads PNG, so the golden harness writes it with a small writer of our own (CRC-32 and Adler-32 from `core:hash`; at first in stored deflate blocks, compressed since 2026-10-29, which took the references from 14 MB to 400 KB), tested by reading its files back. `@(export, link_name = "...")` on a `proc "c"` works for the C ABI (the Odin overview does not say so; Spike 2's `rocinante_main` shows it).
- **API and C ABI:** `examples/circle`, `two_windows`, `garden` and the C example (`tools/abi-check.sh --run`, `-Wall -Wextra -Werror`) run with no errors on every desktop. The ABI check's first run found a real clash (a typedef and a function both named `roci_window`) and a missing Odin verb (`mix` of numbers).
- **Benchmark** (`examples/benchmark`, 100,000 circles a frame through the public API, `-o:speed`): the work counts are exact and tested everywhere (one draw, 100,000 instances, no allocations after the first frame). Frames a second in a window, before and after the speed-ups: Apple M4 Pro (Metal) 60.3 vsync, 123 uncapped; i7-9800X with an RTX 2080 Ti 63.5 on Windows (D3D12) and 64.7 then 116 on CachyOS (Vulkan); invictus (RX 580, Vulkan) 36.7 then 57.8 (17.3 ms against 16.6, accepted for a processor from 2010). The frame is bound by one CPU core on every x86 computer measured. The speed-ups, found with `perf`: the batch hash works out each style and transform once and hashes a whole word at a time (eight multiplies a value cost 11.7 ms headless against 5.6); `finite` checks numbers without branches; `sin` and `cos` use our own kernel; commands are 64 bytes with their looks stored once (184 bytes a command made memory traffic a third of the frame on invictus). SDL's GPU debug mode cost about 0.3 ms a frame and is off by default.
- **Renderer and golden images:** the nineteen golden scenes draw correctly on Metal, Vulkan (NVIDIA, RADV, lavapipe) and Direct3D 12. Against Metal references the other drivers differ only on smoothed edges, and two different Vulkan drivers agreed, so the references were remade on lavapipe and the full `ci` compares lavapipe with lavapipe (exact there, NVIDIA within two steps of a channel). DXIL was made on Windows with the SDK's `dxc` 1.9.2602. Miter is the default join and round the default cap, as in Processing; multisampling replaced a hand-built edge fringe (§4.3).
- **Platform:** runs on macOS, FreeBSD, Windows 11 and CachyOS Linux (niri on Wayland) with no errors. **Higher density** (standing in for a Retina display, §10) was checked with niri at scale 2 and `SDL_VIDEO_DRIVER=wayland`: density 2, everything sharp. SDL 3.4.18 does not use Wayland on niri by default (no `fifo-v1` protocol, so it falls back to XWayland), where a scaled display reports density 1; since 2026-10-29 rocinante asks for Wayland first (§10). Through `xwayland-satellite` on niri 26.04 window settings were lost too: `examples/bricks` (480 by 360, `resizable false`) opened floating at 1701 by 1382, and at exactly 480 by 360 on Wayland. The cost SDL warns about, measured on the i7-9800X and RTX 2080 Ti at 100 Hz: the 100,000-circle benchmark ran at 95 frames a second on Wayland against 100.6 through XWayland, and 1,000 circles at full rate either way.
- **Mobile:** `spikes/mobile/sketch` runs through the public API on a Pixel 9 (all three pipelines, touch moves the circle) and an iPhone 13 Pro (Metal validation on, no errors). SDL on Android counts window sizes in device pixels, so `roci/platform` divides by the content scale there only. An older or lower-end phone moved to Phase 8 (§10).

### Phase 2: The language (done 2026-10-30)
- Lexer, parser, checker, type inference, typed IR, interpreter (§4.7, §5).
- Inference error messages written before the inference rules are final (§5.3).
- `circle at 100 100 radius 50` as a whole program.
- `docs/grammar.ebnf` and source spans on every node, literal and runtime command (§5.14); an error-tolerant parser that resynchronises at `[ ]` and reports every error in one pass (§5.7).
- `roci run` with file watching, hot reload with the state rules of §5.5 (saying whether it reloaded or restarted), `Ctrl+R` restart, error overlay, and the headless options `--frames`, `--screenshot` and `--errors json` (§7).
- The verified example corpus: each example in `examples/` has a task description and a reference PNG, so it doubles as a golden test and as documentation (§9).
- Sketch folders (§4.9): `roci new`, `roci init`, `roci add`, git and optional Git LFS setup, asset lookup by name, the outside-`assets/` error, live asset reload.
- Error message catalogue with tests, including bracket mismatches located by indentation (§5.1), missing argument brackets (§5.1, §5.7) and every `learn`/`give`/`stop` rule (§5.11).
- `roci fmt`: formatting is idempotent (formatting twice changes nothing) and never changes behaviour (formatted and unformatted sketches produce identical frames).
- List verbs (`keep`, `skip`, `collect`, `combine`, `find`, `sort … by`, §5.2).
- Turtle, events, timers, tweens, taught verbs (`learn`, `give`, `stop`, `with` defaults, sharing rules, §5.11), window messaging.
- 2D collision detection (§5.13) with its broad phase.
- Multi-file sketches and `.roci` libraries (§5.10): `use`, `hidden`, `roci get`, `roci update`, `libs/` vendoring, clash rules and their error messages. The public index starts small in Phase 9.
- The typed IR carries what Phase 7's optimisation passes need (§4.7): each block's call site and captures, record shapes per creation site, lists changed inside loops, and whether a value leaves its frame. The interpreter uses them through the shared optimisation passes (§4.7); with the passes off it ignores them, and that run is the reference the others are compared with.
- **Results** (2026-10-27 to 2026-10-30): done are the front end, interpreter, `roci run` and `roci check` and `roci fmt` and `roci man`, sketch folders, several files and libraries with `roci get` and `roci update`, list verbs, events, `every`, window messaging, window settings and `set`, `pressed`, `held`, the rounding verbs, the 2D turtle (`examples/tree`), 2D collision with its broad phase (`examples/bricks`), `tween` and `ease` (`examples/ease`), tables, the window `cursor`, mouse buttons by name with the wheel (`examples/mouse`), and touch (`examples/touch`). Every feature so far has an example: `rays` (`cast`, `inside`, mixed shapes), `sorting` (the list verbs), `tally` (tables), `style` (mixing, stops, joins, caps, named styles, `with`, `oklch`, `shear`), `landscape` (`fbm`, `gaussian`, simplex noise, `every … frames`, `while`) and `windows` (`set`, window properties, `on resize`, `on move`, `on focus`, `on mouse up`) joined the earlier ones on 2026-10-29. Every Phase 1 example is now also written in rocinante (`shapes` and `benchmark` joined on 2026-10-29); `examples/window` stays Odin only, because it tests `roci/platform` itself (raw events, the N, F and V keys), and the language's window settings have `examples/windows`. **The interpreter's speed** (2026-10-29, i7-9800X, RTX 2080 Ti, CachyOS, `roci` built `-o:speed`): `examples/benchmark/sketch.roci` draws its 100,000 circles at 9.7 frames a second, about 100 ms a frame, against 98 frames a second (vsync at 100 Hz, a 3.7 ms draw block) for `main.odin`: roughly 1 µs a loop turn of five statements, 27 times the Odin time. Profiled the same day (`perf`, flat): a fifth of the time went to comparing verb names and a tenth to the map of sketch-wide names and to allocating argument arrays; with verb codes, slots and arguments on the stack a headless frame went from 101 to 61 ms (13 to 14 frames a second in a window). What is left is the tree walk itself (`eval`, nearly half) and real drawing work, so going further means changing how values or nodes are represented, which waits for the benchmark sketches to ask for it (2026-10-27). Later the same day: a copying collector for the sketch's values fixed a memory leak (below, in the code map), calls without style words stopped building a 776-byte look, and the shared optimisation passes (§4.7) gave numbers and conditions a typed path; a headless frame went to 33 ms (53 ms with `ROCI_PASSES=off`; `hyperfine`, five runs, start-up subtracted). What the profile shows now: the typed number path (30%), `sin` and `cos` (17%), drawing (14%), and finding loop names and locals by searching the frame (8%), which numbered frame slots from the checker would remove. The second benchmark, `examples/particles` (10,000 records moved by a taught verb, filtered with `keep` and topped up every frame), runs at 10.6 ms a frame headless and about 60 frames a second in a window; its largest cost outside the walk is finding fields by name (`field_index`, `read_field`, `assign_path`, about 15%), which numbered field indices from the checker would remove. Interpretation speed is closed for Phase 2 (2026-10-29): both figures leave room for working sketches, and released sketches are compiled. Phase 7 compares the compiled sketch with these figures. The newcomer test was run as `tests/newcomer/README.md` describes, and it validated the design: one thing per argument stands (2026-10-30); its sheets and results are kept outside the repository. Every example has its golden reference picture, drawn on lavapipe. Checked by hand on every system at hand (2026-10-29 and 2026-10-30): every example runs on Windows, FreeBSD, Linux and macOS, `roci get` and `roci update` against a real repository, a change to a second file or a library while a sketch runs, `set` on a window (resizing, fullscreen, moving), `examples/garden`'s wind bar and space bar, `examples/bricks` played with the mouse, `examples/mouse` with side buttons and a wheel, the keys of `examples/windows` (its settings are only requests on Wayland), and `examples/touch` on a touch screen. Touch on the Pixel 9 was checked through the phone spike, which draws `roci.touches()` (2026-10-29, built on CachyOS with SDK and NDK 29.0.14206865 in `~/Android/Sdk` and SDL 3.4.18 built for Android in `.cache/sdl-android`): four fingers at once in the right places at 60.2 fps, numbered in order and never reused, the count back to 0 when they lift, and a finger moving the mouse. Touch on the iPhone moves to the release checklist (`docs/release-checklist.md`).
- **Exit**: every Phase 1 example rewritten in `.roci`; every example infers fully (no boxed fallbacks) or the fallback is justified here; a newcomer test (someone who has never seen rocinante makes a moving sketch in 15 minutes, observed), run with two groups that see the same sketches written with one thing per argument and in bare Logo nesting (§5.1), also watching for three traps from Logo's history: `[ 1 2 ]` against `{ 1, 2 }`, a list used where a block belongs, and `b = a` sharing a list or record (§5.1, §5.11). Met on 2026-10-30; the test's results are kept outside the repository.

Met on 2026-11-14 (below).

**Phase 3 results** (2026-11-02 to 2026-11-14; detail is in git history and in §4.3 and §4.8):

- **Spike 5, text** (`spikes/text`; SDL_ttf 3.2.2 through `vendor:sdl3/ttf`, run on macOS with Metal, 2026-11-02): SDL_ttf's GPU text engine (`TTF_CreateGPUTextEngine`) is chosen. It needs only the device, no window. Text in Latin, accented Latin, Japanese, Arabic, Devanagari and mixed scripts all came back as one atlas draw sequence each (a few dozen to 108 vertices), and emoji came as a second, colour sequence (`image_type` COLOR beside ALPHA), so the pipeline needs an alpha-atlas path and a colour-atlas path. Shaping is HarfBuzz's: Arabic joined and ran right to left, and fallback fonts added with `TTF_AddFallbackFont` supplied the CJK and emoji glyphs in a line of Latin. Not checked yet: FreeBSD and OpenBSD packages of SDL3_ttf, Windows and the phones, and a Devanagari font on macOS (the spike's path to it did not exist).
- **Text** (2026-11-02): `text`, `font`, `align`, `leading` and `measure` on SDL_ttf's engine with Inter built in; emoji are drawn apart at the text's size, because a colour emoji font is often pictures at one size (Apple Color Emoji: 160 pixels); installed fonts are copied into `assets/fonts/`, and from the same day the licence only warns (§4.9). SDL3_ttf on Windows comes with Odin (2026-11-05). Known gap: flags draw nothing on macOS.
- **Pictures, canvases, fills, pixels, blend and clip** (2026-11-03 to 2026-11-05): pictures decoded by `core:image` and drawn through the typeset pipeline; canvases with two textures each, because a multisampled pass cannot add to the texture it resolves into; picture fills on shapes, outlines, backgrounds and text (text on the CPU, because the glyph shader has one texture); the pixel verbs as pure CPU work that makes new pictures, with made pictures let go past 256 MB or 2,048; `outline` for collision; `blend` (no `darken`: a minimum colour turned clear corners black) and a box `clip`.
- **Shaders** (2026-11-05): user HLSL translated while the sketch runs by shaderc and SPIRV-Cross (SDL_shadercross has no macOS build), built-in effects, effects on canvases and `shade` fills. GitHub builds SPIRV-Cross from source, because Ubuntu 24.04's package lacks the Metal functions (2026-11-06).
- **Export** (2026-11-05 and 2026-11-06): `save` to PNG (with `#` as the frame number, which gives frame sequences), SVG and PDF from the command list with no GPU (PDF text as glyph outlines, TrueType only), `record` to APNG with nothing installed or to video through the user's ffmpeg.
- **Odin `dev-2026-11`** (2026-11-06): its rewritten `core:compress` changed `Image.pixels` and the image writers, so sancho was patched.
- **Widgets and `ui.toml`** (2026-11-06): the whole widget set of §5.8 except `checkbox` and `controls` (Phase 6), on Dear ImGui with no SDL backend (events fed by hand, so a headless window can be clicked by a test), placing with `at` and `width`, `ui` inside `draw`, hiding by backtick or three fingers, and values remembered in `ui.toml` through our own `roci/toml`. `ui theme` came on 2026-11-11.
- **Screen readers**: the macOS adapter (VoiceOver, 2026-11-09), the Unix adapter over AT-SPI (Orca on Linux 2026-11-09 and on FreeBSD and OpenBSD 2026-11-10, with `espeak` on OpenBSD, which has no `espeak-ng`), and the Windows subclassing adapter (Narrator and NVDA, 2026-11-11). accesskit-c's bindings are generated from its header with every struct measured by a C compiler, because Spike 4's hand-written layouts were wrong. What the hand runs found: Orca speaks a change only from what it holds as the focus, so radio buttons, list items, number steps and open drop-downs had to say they have focus, and the arrow keys now move the value of the widget with focus (2026-11-11); a line of text gives its words as the node's value, or Orca finds it with no name; a radio button is checked, not selected, or UI Automation offers no way to choose one; the Windows adapter must be made before the window is first shown (one blink at start).
- **Windows is Direct3D 12 only** (2026-11-11): SDL is asked for `direct3d12` by name, and a sketch's shaders are compiled by FXC, part of Windows, into DXBC 5.1; DXC was turned down because `dxil.dll` is a closed binary whose licence was not checked. FXC puts globals where SDL binds nothing, so a shader with globals is compiled twice.
- **Tests**: a leak or a bad free fails a test (2026-11-10), and what it found was fixed; golden limits on lavapipe were tightened to a channel of 8 in at most 8 pixels and none past 16 (2026-11-10, against x86-64 Ubuntu, Arch and an Apple silicon Mac); the golden images also run on a Mac with Homebrew's Mesa (2026-11-05), every reference matching the Linux ones to 0 pixels. Traps found on the way (each in the code map's gotchas): SDL's video system started on a test thread crashed ORION (2026-11-06) and a Windows run (2026-11-14); forking among the test threads killed the child about a run in three on macOS, so the ffmpeg tests are the package `roci/movies`; the `cli` tests' drawing hung one pre-push run and crashed another, so they draw nothing and `roci test examples/checks` runs on its own (2026-11-11); Odin's `os.Walker` leaves a folder open on Windows (2026-11-05); a panicking test on Windows can leave the runner spinning; changing the examples at random found two checker crashes (2026-11-11).
- **Exit**: the ten ports (`bounce`, `sinewave`, `rope`, `life`, `flocking`, `koch`, `mandelbrot`, `noisewave`, `recursion`, `colorwheel`, 2026-11-12) are written fresh in the language after the idea of each and have golden pictures on lavapipe, so what is compared is rocinante with itself from run to run; no Processing was run to compare with. `examples/studio` (2026-11-12) was driven by tests with a screen reader's requests, the keyboard and the mouse, and checked by hand with VoiceOver, Narrator or NVDA and Orca, with a finger and with an input method on 2026-11-14.
- **Not done in Phase 3, carried on**: the AccessKit bridge, on-screen keyboards and touch sizing on Android and iOS (to Phase 8, with the phones); video and webcam fills (Phase 6, with video); shaped clips and masks beyond `mask by`; named styles holding a picture; `ui` accent, font and size verbs; custom widgets written by a sketch.

### Phase 4: 3D (done 2026-11-14)

- `mesh` with `as wireframe`.
- 3D collision detection.
- 3D turtle.
- **Exit**: a 3D generative sketch with lights and an imported model running on all platforms (written "all six" before OpenBSD joined). Met on the five desktop systems on 2026-11-14; iOS and Android moved to Phase 8 the same day, because `roci` does not run on a phone and a sketch reaches one only through `roci package`.

**Phase 4 results** (2026-11-13 and 2026-11-14; the design of each slice is in §4.3 and §5.13):

- **Built in slices**: the solids (`box`, `sphere`, `plane`, `cone`, `cylinder`, `capsule`, `torus`, `icosphere`) and the helpers `grid`, `axes` and `arrow`, drawn in a pass of their own with a depth buffer before the 2D pass; the orbit camera and `camera`, `look at`, `ortho`, `perspective`, `screen point`, `world point`; `light`, `no lights` and `material` (physically based, up to 64 lights, because their block must stay under Metal's 4,096 bytes); `shadows` from a sun or spot light and, on 2026-11-14, from a point light as six views in one texture three wide and two high (a cube map was turned down because SDL's cube render targets differ between systems); the turtle in space; glTF and OBJ models with their pictures and extensions; pictures on the solids; collision in space with turned boxes, meshes and `ray` picking; `mesh` and `as wireframe`; `svg` over a new path shape; and the C API for all of it (2026-11-14).
- **Our own model readers**: `vendor:cgltf` ships a library only for macOS and Windows, which would have meant a C build on every other platform for a JSON file and some arrays, so glTF and OBJ are read in plain Odin. Blender's `.blend` and FBX are not read.
- **What real GPUs found**: SPIRV-Cross numbered the Metal shader's textures by first use, so a real Mac read the normal map and the metal and roughness picture swapped (highlights far too sharp) while lavapipe was right; `shaders/compile.sh` now passes `--msl-decoration-binding`. A fragment shader that read the vertex stage's uniform block crashed lavapipe inside its JIT with no message. The DXIL of the 3D and shadow shaders was made on Windows on 2026-11-14.
- **Golden images of lit scenes** have looser limits on lavapipe (`SHADED_PICTURES`: worst channel 40, 60 pixels past 12), because the per-pixel light differs a little between versions of lavapipe's compiler; the textured ship of `example_model` has an allowance of its own.
- **Exit**: `examples/voyage` (a generated city under a sun and a point light that follows an OBJ ship, every shadow cast) and the other 3D examples run on macOS, Linux, FreeBSD, OpenBSD and Windows (2026-11-14).
- **Phone smoke test, Android** (2026-11-14, Pixel 9, Vulkan, built on CachyOS with NDK 29.0.14206865): the phones' sketch (`spikes/mobile/sketch`) grew a page for each phase, chosen by widget buttons, and `roci` now builds for Android: Dear ImGui, SDL3_ttf (with its own FreeType and HarfBuzz), shaderc and SPIRV-Cross are built for arm64 by `spikes/mobile/android/libs.sh` into `.cache/android/lib` (strip the shared ones: shaderc is 149 MB unstripped and 9 MB stripped), and AccessKit is absent there (its stand-ins) until the Android adapter is written. Everything drew at 60.1 to 60.2 frames a second with no error in the log: Phase 1's page; Phase 3's text in Inter with accented letters, a radial gradient, a picture made from colors drawn and as a tiled fill, a canvas keeping a finger's trail, a slider and a toggle driven by touch, and the built-in `vignette` translated from HLSL by shaderc and SPIRV-Cross on the phone itself; Phase 4's lit scene with the sun's and a point light's shadows, a metal torus, a wireframe `mesh` and `examples/model`'s `striker.obj` with its `.mtl` and painted picture, read from bytes inside the program (a file in an APK has no path to open), no picture lost. Not checked: turning the orbit with a finger (the sketch reads the mouse on another page, which keeps the orbit off for the run), text in other scripts and emoji (the fallback fonts list desktop paths), and the iPhone, which Fabrizio runs from a Mac.
- **Not done in Phase 4, carried on**: 3D on iOS and Android (Phase 8); nodes; `wireframe` on the solids and models; per-corner colors and textures on a mesh, and indexed meshes; a shape's alpha in 3D; a gradient on a solid; 3D inside `draw into`; reading the space turtle as a value; an extruded `svg` in space and text as outlines.

### Phase 5: Sound (done 2026-11-15)
- SDL3 audio out and in, playback and streaming, our own synthesis and effects, level and frequency analysis.
- MIDI and OSC, including FreeBSD and OpenBSD.
- Audio-reactive visuals with zero setup.
- **Exit**: an audio-visual sketch controlled by a MIDI controller, latency measured. Met on 2026-11-15 on Linux (below); the other systems' MIDI backends are written from their documentation and checked by hand before each release.

**Phase 5 results** (2026-11-14 and 2026-11-15; the design of each part is in §4.6):

- **Built in slices**: sound files (`load`, `play`, `loop`, `pause`, `rewind`, `forward`, `set` and the fields of a sound); `level`, `bands` and `mic`; instruments (`synth` with `note`, `pitch`, `for`, and an envelope of `attack`, `decay`, `sustain` and `release`); MIDI in (`on midi down`, `up`, `control`, and later `bend`, `program`, `pressure`, `start`, `stop`, with an incoming clock read as `midi tempo`); SoundFonts; sixteen effects and `speakers`; OSC in and out; streaming of long files from the disk and from memory, with a buffer size per sound (`load "song.mp3" buffer 20`); MIDI out (`midi note`, `release`, `set`, `bend`, `program`, `to`, `outputs`, `clock`, `stop`) on CoreMIDI, WinMM and the raw device files; and recording (`record speakers "take.wav"`, a sound or `mic`; WAV written by rocinante, mp3, ogg, flac and m4a through the user's ffmpeg). All of it is in the C API too, and the examples are `sound`, `music`, `keys`, `player`, `soundfont`, `pedals`, `midi`, `midiout`, `osc` and `recorder`.
- **All our own code, no audio library**: miniaudio and stb_vorbis decode (built from the Odin install's own sources, decoding only), and everything else is ours: the mixer, the FFT, the synth, the SoundFont reader, the effects, the MIDI backends, the OSC packets and the WAV writer. `vendor:portmidi` was turned down because on Linux and the BSDs it is a system library `roci` would need at start and it has no phone support, and `fft` as a word because the word must not be technical (`bands`).
- **Latency** (measured 2026-11-15, Linux, PipeWire at 48 kHz, an AKAI MPK mini 3): SDL's own buffer on that system was 1,024 frames, 21.3 ms; asking for 256 frames gives 5.3 ms. With the MPK mini 3, 87 notes waited 4.6 ms on average (11.0 at most) between being read and their `on midi down` block running in the next frame, 12.6 ms on average from a key to its sound leaving the computer. Running MIDI blocks while the loop waits for the screen, and starting each frame late just before the refresh while a sketch reads MIDI (on NVIDIA, where the wait is inside the submit), brought 35 of 37 notes to within 0.7 ms on average, about 8.7 ms from a key to its sound.
- **What a real system found**: on macOS certain notes and chords crackled where Linux did not, and the cause was the mix reaching the device above full scale; everything that goes to the speakers now passes a soft limiter (`mix` itself stays exact for analysis and tests). A stolen voice used to be overwritten with a click, and a note of several layers could take its own earlier layers when all 32 voices were busy; both are fixed. A five-minute song streamed costs about 3 MB, flat.
- **Checked by hand on Linux and macOS only**: MIDI out was listed on this Mac's CoreMIDI; WinMM output, the BSD device files opened for writing and the Windows and BSD input paths are written from their documentation and type-checked for those systems, and wait for the release checklist.
- **Phone smoke test, Pixel 9 and iPhone 13 Pro** (2026-11-16, built on the Mac): the phones' sketch got a Phase 5 page, the one it starts on: a synth and a SoundFont piano played by buttons, a click, a looping rain, a three-minute song read as it plays from a copy of its bytes (the files are carried inside the program, as the ship is), reverb on the speakers, delay on the synth, and `level` and `bands` drawn from what comes out. Both phones played everything, drew at 60 frames a second and made every sound; on Android the song streamed from memory and a seek of 30 seconds landed. **iOS ran Phases 1, 3, 4 and 5 for the first time** (it had run only Phase 1's circle): `spikes/mobile/ios/libs.sh` builds SDL3_ttf with its FreeType and HarfBuzz, shaderc, SPIRV-Cross, Dear ImGui and the sound decoders as static libraries for arm64 into `.cache/ios/lib`, `build.sh` links them (CoreText is needed by HarfBuzz, CoreMIDI by the MIDI code) and AccessKit uses its stand-ins there (the Mac's library is not the phone's). Found: the iPhone's notch and status bar covered the panel's buttons, so the panel now starts inside the screen's safe area (`platform.safe_inset`, from SDL's window safe area); `libs.sh` for Android failed under macOS's `sh` because of an apostrophe inside a `${...:?}` message. A free Apple ID's profile must be trusted on the phone before the first launch. Not checked on a phone: MIDI, OSC, the microphone and recording, the on-screen keyboard and screen readers (Phase 8).
- **Not done in Phase 5, carried on**: AIFF, Opus and AAC files; SoundFont modulators, the filter and the other generators; MIDI, the microphone and recording on iOS and Android (Phase 8; sound itself plays on both); OSC bundle timetags and TCP; `every` with a fraction of a second.

### Decisions that record history

These were dated decisions in `CLAUDE.md` §10. They record how a phase ended or how a problem was found, and bind nothing that the sections they point to don't already say, so they moved here on 2026-11-01.

- **2026-10-24, CLAUDE.md is split**: this file keeps the rules and plan; `docs/design.md` holds §4.3 to §6 and is imported here. Section numbers are global.
- **2026-10-27, Phase 1 exit stand-ins** for hardware not at hand. The benchmark's "mid-range laptop" is replaced by invictus (Xeon X5675 from 2010): every x86 computer measured is bound by the CPU on one core, which is slower there than on any current mid-range laptop, so 60 fps on invictus implies it on such a laptop; the laptop run itself goes to the release checklist. Revised the same day: after the speed-ups invictus reached 57.8 fps in a window (17.3 ms against 16.6), and that is accepted for a processor from 2010 rather than shrinking the GPU instance, which would change the shaders on every system for the last 0.7 ms; the other desktops hold 60 with room to spare. High pixel density is checked through each system's display scaling (Windows at 200%, a scaled HiDPI mode on macOS, a Wayland output scale of 2), which takes the same code path as a Retina panel. A second, lower-end phone is not a Phase 1 exit criterion and moves to Phase 8; frame rates are measured on the Pixel 9 and the iPhone 13 Pro. Full text in `docs/phases.md`.
- **2026-10-30, Phase 2 is closed**: the newcomer test, run as `tests/newcomer/README.md` describes, validated the design, so one thing per argument stands (§5.1) and no rule changes; its sheets and results are kept outside the repository (Fabrizio's decision). Every hand check was done on every system at hand; touch on the iPhone moves to the release checklist.
- **2026-10-30, How the newcomer test runs**: eight people, four per group, in each group two who have never programmed and two with a little experience; group A reads three sketches with one thing per argument and group B the same sketches in bare Logo nesting (a test keeps B equal to A without its round brackets), then everyone builds in the real `roci run`, because bare nesting is an error in rocinante; in person, one at a time, thinking aloud, recorded only with consent, in English. Building in two styles, or a hidden mode that accepts bare nesting, were the other choices. The protocol is `tests/newcomer/README.md`.
- **2026-10-29, Wayland first, on mango** (from the Wayland decision in §10): **Mango on invictus (FreeBSD 15.1)** was not an X11 problem: SDL was on Wayland there, but a window is made resizable and `resizable false` comes after, and mango answers the new window with a configure of its own size (1495 by 1022, no states, from `no_size_hint`); SDL pinned whatever size the window had when it was fixed. `roci.set_resizable` now sets the window back to its own size before fixing it (checked with `WAYLAND_DEBUG=1`: mango configures 480 by 360). This is a hand-checked path, since headless windows have no SDL handle.
- **2026-11-14, Phases 3 and 4 are closed**: Phase 3's hand check of `examples/studio` (screen readers, touch, an input method) passed, and 3D runs on the five desktop systems. The phones' part of both (3D, the screen-reader bridge, the on-screen keyboard and touch sizing on iOS and Android) moved to Phase 8, where `roci package` brings a sketch to a phone (Fabrizio's decision), and the counts that said "six platforms" from before OpenBSD joined now say seven.
